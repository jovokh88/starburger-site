# Starburger visual QA — 2026-09-24

## Baseline and scope

Baseline design commit: `7ed4c7846e7f9798a8823ef36f1ca32fd9c6a808`.
Production was not changed during the QA runs. Tests run against a locally built production server on isolated GitHub-hosted runners; external analytics, Telegram, phone and map requests are not sent.

## Changes

- Replaced full-bleed enlargement of a portrait menu photograph with a separately framed hero photo; responsive bottom-aligned crop removes the printed menu label from the hero.
- Corrected responsive toolbar visibility, narrow-screen headline wrapping and zero-height sixth gallery cell.
- Used six existing photographs of the actual venue instead of repeating product pictures in the atmosphere gallery.
- Added accessible native dish-detail dialogs with Escape dismissal and focus restoration; retained the existing external order destination. Clicking a dish is not represented as a completed order.
- Rendered `uz`, `ru` and `en` HTML languages on the server. Unknown locales return 404. The root redirects to `/uz`.
- Replaced continuous marquee/spinning effects with finite entrance, hover and dialog transitions; respects reduced-motion preferences.
- Updated only sharp's lockfile entries and its platform binaries from 0.35.3 to 0.35.4. Next.js 16.3.3 and React 19.2.8 remain unchanged.

The one-off repair workflow with write permission was removed after producing the reviewed lockfile commit.

## Not claimed / still outside this pass

- No physical iPhone/Android-device test or measured real-user Core Web Vitals.
- No verified business conversion rate, visitors count, completed orders or confirmed ingestion of custom analytics events.
- The on-site dishes remain a selection; the full menu stays in QRCHA. Full on-site menu/search and automatic menu-price synchronization are not implemented.
- Prices were retained from the existing repository, not independently reconciled to a current POS/catalog export.
- Main-domain production promotion is a separate deployment action; a READY preview must not be described as production.
